# INT8 Output-Stationary Systolic Matrix Multiplier (4x4) with PicoRV32

A Verilog design that multiplies two 4x4 signed INT8 matrices into 32-bit results.
It has a serial-I/O wrapper for a small FPGA pin count, and a PicoRV32 SoC that
drives the array through memory-mapped registers.

## Status

Verified in simulation (Icarus Verilog):
- `rtl/matmul_simple.v`: 4x4 matrix multiply, checked against a reference
  (identity, -128 x -128 corner case, 20 random pairs).
- `rtl/systolic_os_4x4.v` with `rtl/pe_os.v`: output-stationary array with skewed
  inputs, checked against reference matmul (one fixed pattern and six back-to-back runs).
- `rtl/systolic_top.v`: serial-I/O wrapper (LOAD / RUN / READ FSM), checked over six
  runs with reset and six back-to-back runs without reset.
- PicoRV32 (`rtl/picorv32.v`) fetches and executes a hand-encoded program
  (`sim/tb_cpu_fetch.v`, `sim/tb_cpu_store.v`).
- `rtl/soc_mini.v` + `rtl/accel_mmio.v`: the CPU, running a program generated by
  `sim/gen_prog.py`, copies A and B into the accelerator, starts it, polls done, and
  copies C back to RAM. The 16 results match the reference (`sim/tb_soc_mini.v`,
  one random seed).

Synthesis and place-and-route (Yosys + nextpnr-ecp5, LFE5U-45F, 25 MHz target):
- `systolic_top` fits: 7 I/O pins, 16 of 72 multipliers, 45.7 MHz estimate.
  This is a fit and timing estimate, not a hardware test.

## Not yet done
- No hardware run. The LPF (`constraints/ulx3s_systolic.lpf`) and pin map are
  reference material only; the design has not been programmed onto a board.
- Firmware is generated by a Python script with hand-checked encodings, not compiled C.
- The SoC has not been synthesized or place-and-routed.
- No tests for host misbehavior (early start, wrong bit counts).
